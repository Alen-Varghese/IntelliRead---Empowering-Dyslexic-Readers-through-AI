# IntelliRead

An explainable, rule-based system for dyslexia screening and reading support.
A learner copies a reference passage by typing, speaking or uploading a photo of handwriting.
IntelliRead aligns the two texts word by word, classifies every mismatch (substitution, omission,
insertion, transposition, reversal) and gives a repeatable screening score with the error list behind it.
Google Gemini is used only to word the recommendations and to read handwriting; it never sets the score.

## How it works

1. **Input** – typing, browser speech-to-text, or handwriting OCR (Gemini vision, Tesseract.js fallback)
2. **Normalise** – tokenise, lowercase, strip edge punctuation
3. **Align** – longest common subsequence over words, so one missing word does not shift the rest
4. **Classify** – character rules give one of five error types
5. **Score** – error rate × 2.5, capped at 95%; texts under 10 words × 0.7 with a 40% floor

## Project layout

| Path | What it is |
|---|---|
| `src/` | React + TypeScript front end (Vite) |
| `supabase/functions/` | Source of the prediction, OCR and evaluation functions |
| `server/index.ts` | Local Node.js API that runs those functions (used by `npm run dev`) |
| `api/` | Vercel serverless functions; `api/_lib` is generated by `npm run gen:api` |

## Run locally (Windows)

Double-click `run-intelliread.bat`, or:

```sh
npm install
npm run dev        # web on http://localhost:8080, API on :8787
```

Optional: create `.env.local` with

```
GEMINI_API_KEY=your-key
GEMINI_MODEL=gemini-3.8-flash
```

Without a key, scoring still works; recommendations use the built-in list and OCR uses Tesseract.js.



## Deploy on Netlify

1. Import this repository at app.netlify.com (Add new site → Import an existing project). `netlify.toml` sets the build command, the publish folder and the functions.
2. Under **Site configuration → Environment variables**, add `GEMINI_API_KEY` (and optionally `GEMINI_MODEL`).
3. Deploy, then open `/api/gemini-test` on your site to check the key. Without a key the site still works, using rule-based scores and built-in recommendations.

The same `api/` handlers also run on Vercel through `vercel.json`.

## Checking the reference text

The learner's text is compared with the reference text, so a mistake in the reference would otherwise be blamed on the learner. Each run therefore also checks the reference:

- **Misspelled reference words** (for example "teh"): if a reference word is not in the English word list (`supabase/functions/predict/english-words.ts`, from the SCOWL/Hunspell en_US dictionary) and the learner's word is, it is not counted against the learner and a fix is suggested.
- **Real words that do not fit the sentence** (for example "form" for "from"): when a Gemini key is set, Gemini is asked which word fits the sentence. It never changes the score; it only suggests a fix. This check sends both texts to Google.
- **Wrong passage**: if fewer than half of the reference words were copied exactly or nearly, the page warns that the texts may not be the same passage.

The page lists these with a **Fix reference text and re-check** button, which applies the suggested fixes and scores again.
